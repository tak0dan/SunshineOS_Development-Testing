# Cross-distro stability/sustainability decisions → SunshineOS milestone evolution

**Scope:** 11 systems (EndeavourOS, Omarchy, Garuda, Artix, SteamOS, CachyOS, Obarun/66, Windows, macOS, OpenBSD, GhostBSD).
**Goal served:** milestone-based evolution — Arch = milestone 0, current SunshineOS = 0.9, each release = next milestone — that succeeds from any historical state after any number of years.
**Baseline assumed (from local repo, not re-audited):** signed trust root (Stage A), signed sandboxed adapters, declarative transformation plans, journal/checkpoints, post-migration `--verify`. `README.md`, `TODO/TODO_Migration.md`.

Method: facts verified with websearch/webfetch; inline `[S#]` markers resolve to the URL list at the end. Claims are limited to what those sources state; no design detail is invented.

## 1. Per-system comparison

| System | Stability / sustainability mechanism (verified) | Evidence / source | Concrete SunshineOS design decision suggested |
|---|---|---|---|
| **EndeavourOS** | Pure Arch rolling release on Arch stable repos; community consensus that frequent *small* updates produce smaller breakages than large batched jumps, and that snapshots make rolling release safe rather than undermining it. Automated pre-upgrade snapshots (Timeshift/Snapper; `timeshift-autosnap` pacman `PreTransaction` hook with `AbortOnFail`). Mirror health matters: slow/far mirrors make updates fail mid-download; welcome app switches to fastest/closest mirror. | [S1][S2][S3][S4] | **Snapshot-before-update as a mandatory checkpoint** in every milestone plan; prefer many small milestone steps over rare large jumps; **transport/mirror preflight** before any download-bearing operation; snapshot creation must be `AbortOnFail` (no silent proceed without checkpoint). |
| **Omarchy** | **Blessed update path guard:** raw `pacman -Syu`/`yay -Syu` is stopped and redirected to `omarchy update`, because snapshot + migrations + config updates must travel with the packages (single-transaction bypass exists). Rollback = pick pre-update snapshot in bootloader. Four channels (stable, RC, edge, dev); stable uses an Arch mirror held **one month behind** to catch incompatibilities needing config changes. `omarchy reinstall` is a last resort that resets config and downgrades packages — explicitly destroys user config changes. | [S5][S6][S7] | **Blessed update path guard hook**: reject direct `pacman -Syu` on a SunshineOS-managed machine, route to the milestone engine. **One-time post-upgrade hooks** bundled atomically with each milestone. **Channel strategy** (stable/RC/edge/dev with a deliberately delayed mirror) for milestone candidates. Do **not** copy `omarchy reinstall` semantics: preserve user config via three-way merge, never wholesale reset. |
| **Garuda Linux** | BTRFS-first design with Timeshift snapshots created in a pacman `PreTransaction` hook ("Creating Timeshift snapshot before upgrade…", `AbortOnFail`) and bootable snapshots exposed through GRUB (`grub-btrfs`). Rollback is a boot-time choice, not a reinstall. | [S8][S3][S4] | **Snapshot-before-update** integrated into the transaction manager, plus **bootable snapshot entries** registered as part of the milestone commit checkpoint; verification must confirm the boot entry exists before marking a milestone complete. |
| **Artix Linux** | systemd-free Arch fork with init system as an explicit install-time choice (OpenRC, runit, s6, dinit/SysVinit) and its own repos + AUR. Compatibility limits are declared, not hidden: GNOME support was discontinued as GNOME's systemd dependencies deepened; documented systemd→alternative-init migration guides exist; some upstreams answer "no way to remove systemd and still be Arch". | [S9][S10][S11][S12] | Treat **init/supervisor as a first-class discovered fact** in capability discovery (`source_profiles.init_system`), not an assumption. **Fail preflight with a precise blocker** for unsupported combinations instead of forcing conversion. **Retire a component when upstream dependency conflict makes support untenable** (the GNOME precedent) rather than shipping a silently broken adapter. |
| **SteamOS** | Image-based, atomic **A/B slot** updates via RAUC + Casync: write to inactive partition, reboot into it, previous known-good slot ("Previous B") retained for recovery. Root filesystem read-only by default (`steamos-readonly`); explicit `atomic-update-keep.conf` keeplist for files that must survive an update; same image delivered to all users even if they disabled read-only and edited files. Channels via `steamos-select-branch` (Stable/Beta/Preview). Update assembly uses a **pre-determined plan**, regenerates invalid seed indexes, and validates written chunks when a seed chunk is invalid. | [S13][S14][S15][S16][S17] | **Retained previous state / rollback** at every milestone boundary (bootable previous slot, not just a data backup). **Immutable target baseline + explicit keeplist** for user config (mirrors upstream preservation). **Channel strategy**. Make plans **deterministic and self-validating**: detect stale/invalid cached artifacts and regenerate/re-verify rather than trust them; `post-migration --verify` should validate what was actually written. |
| **CachyOS** | BTRFS + Snapper + `snap-pac` pre/post pacman hooks + bootable GRUB/Limine snapshots by default. Documented limits: ~10 snapshots max (older ones create compatibility issues); snapshots cover root subvolume only, `/boot` (ESP) is excluded, so rollback can produce kernel/module mismatch; both documented restore paths first boot into the snapshot's **own kernel** as the mitigation. | [S18][S19][S20] | **Free-space/retention preflight** and a bounded support window for snapshots (do not accept arbitrarily old historical states as valid sources). Snapshot/checkpoint must be a **coupled set** — kernel + initramfs + modules + boot artifacts — validated together, matching the engine's "Validate boot artifacts" checkpoint. Use **boot-into-snapshot-then-commit** restore protocol for boot-affecting milestones. |
| **Obarun (66 on s6)** | Automatic `system@<version>` snapshot of the 66 ecosystem **before** migration; `snapshot restore` + package downgrade returns the system exactly. 0.9.2.0 migration is automatic and **works without reboot**; triggered lazily by the first `66` command, per-user ecosystem migrated separately. Single-pass migration from any 0.8.x/0.9.0.0; below 0.7.2.1 = **fatal error, no path**. "A broken service no longer stops everything": skip broken service + dependents and name the repair command (`66 reconfigure -c`). "Commands you can trust": refusing one named service changes **nothing**; two concurrent commands **serialize** instead of overwriting each other. Dependency graph is a declared-DAG resolved recursively, inspectable with `--graph`/`--reverse`/`--depth`; snapshot is a verbatim copy of ecosystem dirs and is portable machine-to-machine. Obarun left s6 to **own the supervisor's state vocabulary** rather than ride an upstream release treadmill. | [S21][S22][S23][S24][S25] | **Named checkpoint per from-milestone** (`system@<from>`); **lazy one-time migration** triggered by first engine command; **explicit support floor** — unsupported old states get a fatal, precise error, not a guess. **Concurrency lock** (serialize concurrent engine runs). **All-or-nothing operation groups**. **Failure isolation**: skip a broken component and its dependents, emit the exact repair command. Keep a **declarative DAG with graph inspection**, and own the state contract rather than depending on an upstream churning one. |
| **Windows** | **Servicing stack updates** update the updater itself (SSU contains CBS) to improve update reliability. **WinSxS component store**: one full copy per component version, hard-linked into the filesystem; forward **and reverse differentials** to base versions are stored, enabling uninstall/rollback; `ResetBase` removes superseded versions and thereby removes uninstall ability. **Transactional staging** with commit/rollback (CBS: "error occurred while committing the transaction, the transaction has been rolled back"). Files held open are deferred to a **primitive operations queue** (`WinSxS\pending.xml`) executed at boot by `poqexec.exe`. `\Windows\servicing\sessions\sessions.xml` logs every servicing transaction; `CBS.log` is the primary log. **DISM `/ScanHealth`/`/RestoreHealth` + SFC** repair from the component store. Deleting `pending.xml` blind is an "amputation" — journal + actual state must be reconciled. | [S26][S27][S28][S29][S30][S31][S32][S33] | **Self-updating engine** (servicing-stack analogue): allow milestone 0.9→N to patch its own adapter/engine before transforming the target. **Retained previous component versions** with differential artifacts for uninstall/rollback. **Transactional staging** with explicit commit/rollback in the journal. **Persistent transaction log** (sessions.xml analogue) recording every milestone transaction. **Deferred boot-time operation queue** (pending.xml analogue) for changes that cannot be applied safely live (kernel/boot). **Repair/verify command** stronger than `--verify`: reconcile actual state against the signed manifest; never delete the journal blindly (matches `TODO_Migration.md` §9.4). |
| **macOS** | Read-only system volume (10.15) + **Signed System Volume** (11+): per-file SHA-256 in filesystem metadata, recursively hashed into a Merkle tree whose root **seal** covers every byte; Apple signature covers the whole volume. Verified **on every read** at runtime and **at boot** (Apple silicon bootloader before kernel; Intel T2 forwards measurement to kernel before mounting root); mismatch halts boot and prompts reinstall; repeated every boot. **APFS snapshots**: if an update fails, the old system version is restored **without reinstallation**. **Authenticated root** enabled/checked via `csrutil authenticated-root`; disabling requires Recovery and is refused if FileVault is on. | [S34][S35][S36][S37] | **Signed sealed state verification at read time and at boot**: extend Stage A to a signed hash-tree root over the post-migration system state, checked by `post-migration --verify` and again at boot. **Restore old system version without reinstallation** = previous milestone state must itself be bootable/sealed, not merely backed up. **Authenticated-root-style fail-closed policy** gated behind Recovery. Keep the sealed system state separate from user data/config (the SSV/Data volume split) so upstream/user files are preserved. |
| **OpenBSD** | **Separate update layer per trust domain:** `syspatch(8)` applies signed binary base-system errata (and can roll them back); `sysupgrade(8)` does the in-place release upgrade; `pkg_add -u` updates packages — base fixes do not touch packages and vice versa. `bsd.rd` ramdisk installer/recovery kernel is verified with `signify` against the release public key before being booted for manual upgrades. `fw_update(8)` downloads firmware as an unprivileged user, then verifies a `signify`-signed `SHA256.sig` before root installs it; packages are signature-checked by `pkg_add`. One rolling `-current` trunk; stable release ~every 6 months, each supported 1 year (two releases live); errata backported to both. `securelevel(7)` has four levels, raisable at runtime but lowerable only by init; `pledge(2)`, `unveil(2)` and `chroot(2)` reduce process privileges. | [S38][S39][S40][S41][S42][S43][S44][S45] | **One signed trust root per layer** (base / firmware / packages), each with a signed checksum manifest — strengthens Stage A beyond a single key. **Staged activation via a signed, verified recovery kernel** (`bsd.rd` analogue) for boot-affecting milestones. **Sysmerge-style config reconciliation** and one-time post-upgrade hooks. **Capability-based privilege limits for adapters** (`pledge`/`unveil`/`chroot` analogue) beyond sandbox limits. **Bounded support window** (two releases) → published milestone support floor; `-current` snapshots vs supported release → **channel strategy**. |
| **GhostBSD** | **FreeBSD-based, not Arch-based.** ZFS-only installer defaults (GBI dropped UFS); ZFS boot environments via `bectl(8)` (`beadm` predecessor) with `bectl activate -t` boot-once for safe testing; Update Station creates a **BE backup before upgrading**, Backup Station manages BEs via in-house `pybectl`. Base updates moved from source tarballs/`freebsd-update` to **PkgBase** (`pkg`-driven OS updates) in 2018, then to FreeBSD-maintained PkgBase in 2024; in 2025 the project moved from FreeBSD STABLE back to **RELEASE (14.2-RELEASE-p1)** for stability. MATE (GTK) flagship + Xfce option, LibreOffice/GUI apps bundled; mission is "usable desktop out of the box". | [S46][S47][S48][S49][S50][S51][S52] | **Staged activation with boot-once + retained bootable previous BE** as the milestone commit gate. **Base-vs-package layer separation** (PkgBase) → keep milestone base state distinct from adapter/package layer. **Conservative upstream selection** (RELEASE over STABLE) → channel strategy. **Capability-based qualification + assessment-only path**: not bootstrappable via pacman/libalpm, so a GhostBSD source requires a separate source profile or read-only assessment, never a transform-to-Sunshine target. |

## 2. How each system informs SunshineOS's evolutionary migration mechanism

### 2.1 Guard, support floor, and self-renewal (the "any historical state" precondition)

- **Omarchy** → a **blessed update path guard hook** is the cheapest way to guarantee that migrations actually run: forbid the raw package-manager path on managed machines. SunshineOS already ships a `sunshine-update` entry point; make it the only accepted path, with an explicit documented bypass (Omarchy's single-transaction bypass is the precedent).
- **Obarun** → milestone-based evolution needs an **explicit support floor**, not universal promises. Arch=0 → 0.9 → N should mirror Obarun's table: each milestone declares the minimum from-milestone it can migrate; below it, abort with a precise "no path" fatal. This is the honest implementation of "succeeds from any historical state": any *supported* historical state, with the floor published.
- **Windows** → an **SSU-style self-update** lets an ancient bootstrap (milestone 0.9) patch its own engine/adapters before it can understand milestone N's target. Do this in Stage A before any target transformation.

### 2.2 Preflight, snapshots, and coupled state

- **EndeavourOS / Garuda / CachyOS** → **snapshot-before-update** with `AbortOnFail`, **free-space preflight**, and a **retention bound**. CachyOS's documented kernel/module mismatch is the critical refinement: a checkpoint is only valid if it is a *coupled set* (kernel + initramfs + modules + `/boot` artifacts). SunshineOS's boot-integration checkpoint should verify that set before declaring a milestone applied.
- **SteamOS / macOS** → the strongest form of retained previous state is a **bootable previous slot/snapshot** (A/B, APFS), not a backup archive. A failed milestone should revert by selecting the prior sealed state, with no reinstallation.
- **Artix** → preflight must read `init_system` from discovery and reject unsupported combinations rather than adapting blindly; a declared compatibility profile is a stability feature.

### 2.3 Execution discipline

- **Obarun** → four concrete executor properties: **concurrency lock** (serialize two engine runs), **all-or-nothing per operation group** (a refused step changes nothing), **failure isolation** (skip a broken component plus its dependents and name the repair command rather than halting the whole boot/migration), and an **inspectable dependency DAG** (`--graph`/`--reverse`/`--depth` analogue) over declarative plans.
- **Obarun (why it left s6)** → own the **state contract** (schemas, result vocabulary) instead of inheriting an upstream project's release treadmill — directly relevant to SunshineOS owning its component schema versions across milestones.
- **Windows** → pair the existing journal with a **persistent transaction log** and a **deferred boot-time queue** for ops that cannot be applied live; add a **DISM/SFC-style reconcile-and-repair** mode that compares actual state to the signed manifest. Reconciliation uses journal *and* live inspection; never trust or delete the journal alone.

### 2.4 Verification channels and history policy

- **macOS** → extend `post-migration --verify` from a one-shot check to **signed seal verification on read and at boot**, with a fail-closed halt on mismatch; keep user data outside the sealed set.
- **Omarchy / SteamOS** → **channel strategy** (stable/RC/edge/dev; Beta/Preview), with a deliberately delayed stable mirror, gives milestones a soak period before they become the default target.
- **CachyOS / EndeavourOS** → bounded snapshot history and many small steps are the practical answer to "years later": do not promise migration from an unbounded set of stale snapshots; promise it from a published, tested set of milestone states.

### 2.6 OpenBSD — layered trust and bounded support

- **Layered signed artifacts** → SunshineOS should not have one monolithic trust decision. Base state, firmware-like external artifacts (adapters), and packages each get their own signed manifest key, verified before use; this is a direct extension of Stage A. The `bsd.rd` pattern adds a **signed recovery/upgrade kernel** that performs the transformation, so the agent doing the migration is itself verified and independent of the state being migrated.
- **Base/ports separation** → the milestone target must name a base state and a package/adapter state separately; a milestone can change one without forcing the other, and a failed adapter upgrade must not be reported as a failed base migration.
- **Least privilege** → `pledge`/`unveil`/`chroot` are the strongest precedent for the signed adapters' sandbox limits: declare the exact capabilities an adapter may use, enforce at the kernel/executor boundary, and make violations fatal rather than best-effort.
- **Cadence** → "one rolling trunk, two supported releases" is the same discipline as the engine's published support floor: the milestone graph keeps a bounded set of valid source states, and anything older gets a precise unsupported-state error rather than a speculative migration.

### 2.7 GhostBSD — staged activation, and the non-Arch boundary

- **Boot environments** → a ZFS BE is the closest analogue to a milestone commit point: create a named BE before the change, test with `activate -t` (boot-once), and only permanently activate after verification. SunshineOS's `--verify` should therefore gate a **staged activation**, with the previous milestone remaining bootable until the new one is confirmed.
- **Base vs packages** → GhostBSD's move to PkgBase reinforces keeping the milestone base state separate from the adapter/package layer, so rollback of one does not drag the other.
- **Conservative upstream** → choosing FreeBSD RELEASE over STABLE after maintenance cost grew is a channel/soak decision; SunshineOS should pin milestone targets to a conservative upstream Arch snapshot rather than a moving trunk.
- **Not Arch-based — explicit qualification** → GhostBSD cannot be bootstrapped via pacman/libalpm, so the Arch→Sunshine transformation does not apply. It must be modelled as a **distinct source profile with capability-based qualification**, and for now an **assessment-only path** (discover and report, never claim convergence). This matches the pre-existing limit that the five-year guarantee covers supported source profiles only, not arbitrary installations.

### 2.8 Cross-cutting note: how the two new systems reinforce existing decisions

OpenBSD's signed-base/ports separation and GhostBSD's ZFS boot environments are independent confirmations of five decisions already in the mapping above: **signed sealed-state verification** (OpenBSD's per-layer `signify` manifests and signed `bsd.rd` mirror the macOS-style seal idea at artifact granularity); **immutable baselines** (a signed OpenBSD base set, and a ZFS BE that is not mutated in place, both keep a known-good state untouched while the new one is prepared); **staged activation** (`bsd.rd`-driven upgrade and `bectl activate -t` boot-once both activate only after the candidate is ready); **capability-based qualification** (OpenBSD's `pledge`/`unveil` for processes and GhostBSD's per-source ZFS/RELEASE profile facts both argue for declaring and enforcing what a component or source may do, rather than assuming it); and an **assessment-only path for non-Arch sources** (GhostBSD is the concrete case: no pacman/libalpm bootstrap means qualification and reporting, not transformation).
