### **Medium-Priority Findings**
- **M-04 vs Agent Assignment:** Centralized "work can not stop" directive overrides the invariant that the installation is authoritative. The mandate treats the migration program as the arbiter, not the system state.
- **M-05 vs M-06 Tension:** The 76-hour mandate explicitly suspends the staging/recovery cycle that M-05 and M-06 mandate. A compromise (e.g., staged checkpoints within the 76-hour window) is needed for compliance.
- **M-07 vs Distro Downloads:** The mandate downloads 9 distinct OS ISOs. Without immutable archival (hashes/signatures per M-07), migration paths become fragile.

## 3. Prioritized Defect List with Exact Corrections

### **P0: Critical – Incompatible Workflow Model**
- **Defect:** The 76-hour continuous-work mandate (M-01, M-05, M-06) is fundamentally incompatible with the evolutionary migration model's invariants.
- **Correction:** Replace the "work can not stop" clause with a *staged-checkpoint* model. Define maximum 4-hour migration sub-sessions with explicit recovery journals, aligned with M-05/M-06. The orchestrator assigns tasks per session; interruption resumes from last journal hash.
- **Path:** `reports/USER_MIGRATION_MANDATE_2026-11-21.md` – amend the 76-hour program clause to a `4-hour-session` model with `MIGRATION_JOURNAL_HASH` metadata.

### **P1: Critical – Unarchived External Dependencies**
- **Defect:** Downloading ISOs and researching live distros (M-07) without immutable artifact identifiers creates unrecoverable migration paths.
- **Correction:** For each distro downloaded, generate a `SHA3-256` hash, Ed25519 signature, and metadata block (`event_id`, `schema_version`, `compatibility_meta`). Store in `evidence/distro_audit/` with immutable naming: `distro-<name>-<hash>.json`.
- **Path:** `reports/USER_MIGRATION_MANDATE_2026-11-21.md` – add artifact archival protocol after the "Download..." clause.

### **P2: High – Evolution History Mutability Assumption**
- **Defect:** The mandate's "copy their strongest tools and decisions" (M-02) assumes evolution history can be modified, contradicting the immutable ledger requirement.
- **Correction:** Decouple *tool adoption* from *evolution history modification*. Adopt tools as immutable artifacts (hash-signed) in `evolution-engine/transitions/`, tagged with `adoption_source` but not altering the core ledger. Evolution events (`E001`–`E040`) remain signed and unchangeable.
- **Path:** `evolution-engine/` – create `adoption_catalog/` separate from `ledger/`.

### **P3: High – Qualified Support Assumption**
- **Defect:** M-08 violated by assuming all distro integrations are valid without per-component testing.
- **Correction:** Implement a `transition_qualification_gate()` in the orchestrator. Each component (package, service, hook) from adopted distros must pass a qualification test suite before catalog entry. Failures logged in `evidence/qualification/` with `component_id`, `test_result`, `rejection_reason`.
- **Path:** `evolution-engine/orchestrator.py` (or equivalent) – add gate; mandate clause updated to reference the gate.

### **P4: Medium – Repeatability Under Continuous Assignment**
- **Defect:** Agent assignment model (2 subordinates per agent, 76 hours) risks uncontrolled duplication on re-run (M-09).
- **Correction:** Introduce idempotent task identifiers (`TASK_ID=<uuid>`, `SESSION_ID=<uuid>`). The orchestrator checks `autonomy/results/` and `autonomy/qc/latest.md` for completed `SESSION_ID` before dispatch. Duplicate dispatch blocked with `ALREADY_COMPLETED` status.
- **Path:** `autonomy/agent_dispatch.py` – add idempotency check; mandate clause updated to reference session tracking.

### **P5: Medium – User Data vs OS Reconstruction Blur**
- **Defect:** The reparation mechanism described ("completely repair the systems services, packages, daemons, instabilities, fstab, initramfs") risks violating M-10 by treating OS and data as conflated.
- **Correction:** Split the reparation tool into two distinct profiles:
  - `os_repair/` – services, packages, daemons, initramfs, boot.
  - `data_restore/` – user configs, home directories, fstab (as data, not OS).
  Profiles operate on separate state snapshots with independent validation.
- **Path:** `evolution-engine/repair/` – restructure into `os_repair/` and `data_restore/`; mandate clause updated.
