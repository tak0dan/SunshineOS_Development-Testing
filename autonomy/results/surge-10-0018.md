**Recovery Procedure (runit):**
1. Boot from Artix ISO `x86_64` with `runlevel=3` prompt.
2. Mount `/dev` `/proc` `/sys` into chroot.
3. Run `sv up /etc/runit/sv/` to enable critical services.
4. Validate boot: `runsvok /etc/runit/sv/` → exit code `0`.
5. Journal entry: `/var/log/runit/journal.log` entry `BOOT_RECOV_001`.
6. Compensating step: `sv down /etc/runit/sv/<service>` if validation fails.

**Recovery Procedure (openrc):**
1. Boot from Artix ISO `x86_64` with `prompt` parameter.
2. `chroot` into installed system.
3. Run `rc-update add <service> boot` to re-enable critical services.
4. Validate: `rc-status` → all services show `started`.
5. Journal entry: `/var/log/rcboot.log` line `BOOT_RECOV_002`.
6. Compensating step: `rc-update del <service> boot` if validation fails.

## 5. Migration Integration Notes
- These recovery catalogues feed directly into the **Migration Executor** (`evolution-engine/`) as stage-1 validation checks.
- Run-level states are treated as **historical anchors** per invariant **M-01**: the system resolves toward a target boot state rather than replaying release scripts.
- Recovery procedures are versioned under `TC18` (Transition Catalog) and can be re-executed via `autonomy/engine` without dependency on the original Arch release history.
- Interruption recovery: if a boot recovery operation is interrupted, the journal (`rupertd-log-005.log` or `rcboot.log-017.log`) provides explicit compensating commands to return to the pre-operation state.
