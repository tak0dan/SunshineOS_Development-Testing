- All service symlinks must be verified as non-broken for a valid recovery state.
- Logs in `/var/log/runit/` are the primary evidence for interrupted or failed boot sequences.

**Notes:**
- openrc's authority resides in `/etc/rc.conf` and the runlevel symlink directories.
- `/etc/conf.d/local.start` is the last opportunity to inject custom recovery logic before the system is considered "up".
- Service enablement is purely symlink-based; broken symlinks = unsupported state (Invariant M-08).
- Boot log at `/var/log/openrc.log` must be parseable for interrupted-state detection.

## 5. Test ID Mapping & Recovery Validation

| Test ID | Purpose | Validation Criterion |
| ------- | -------- | -------------------- |
| `ARTIX-BR-001` | Verify `/etc/runit/1` executes without error in chroot | Exit code `0`; all `sv` dirs resolvable |

| `ARTIX-BR-012` | Validate all default-runlevel symlinks are absolute paths | No relative symlinks; target exists |
| `ARTIX-BR-015` | Parse `/var/log/openrc.log` for "OK" status on critical services | At least 95% of listed services report `OK` |

**Recovery Workflow (per Invariant M-06):**
1. **Discovery:** Scan file paths above; record current state hashes.
2. **Staging:** Propose modifications in `/tmp/recovery_staging/` (never modify `/etc` directly).
3. **Validation:** Run test IDs; if any fail, abort and journal the attempt.
4. **Execution:** Apply only passing modifications.
5. **Recovery:** If validation fails, restore from archived hashes (see `evidence/artix/recovery_snapshots/`).
