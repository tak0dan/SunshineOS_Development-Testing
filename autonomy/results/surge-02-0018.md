## Verification & Recovery Framework

- **Staged Execution:** All recovery operations staged in `autonomy/results/artix/` before applying to running system (invariant M-05).
- **Journaling:** Every boot recovery operation logged to `logs/artix-*.log` with immutable timestamps. Re-running discovery (invariant M-09) produces idempotent scripts; no uncontrolled duplication.
- **Compensating Procedures:** Each recovery rule in `openclaw/artix/` includes explicit compensating steps (invariant M-06). If validation fails, engine invokes recovery baseline `B-1-2015` without destroying accumulated user state.
- **Historical Anchors:** `B0-2026` (canonical Arch 2026 baseline) and `B-1-2015` (older recovery anchor) referenced in all migration plans. Evolutionary ledger `E001`–`E040` provides immutable change sets (invariant M-02).
- **Target-State Driven:** Migration does not depend on sequential release replay. Target profile `TP040` resolves desired boot configuration from historical state (invariant M-01).
