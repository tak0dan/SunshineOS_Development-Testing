## 3. Comparative Recovery Matrix

| Dimension | runit (`ART-BR-001`/`003`/`004`) | openrc (`ART-BR-005`/`007`/`008`) |
|-----------|-----------------------------------|-----------------------------------|
| **Init Model** | Supervise tree, `runsvdir`, `sv` commands | Script-based `/etc/init.d/`, `rc` commands |
| **Boot Timeline** | Faster (parallel `runsvdir` start) | Sequential (`bootmisc`, `bootwait`) |
| **Failure Detection** | `sv status` + signal handling | `rc-status` + `/run/openrc/softlevel` |
| **Recovery Idempotency** | High (per-service `sv restart`) | Moderate (global `rc-service restart`) |
| **fsck Integration** | Dedicated hook (`runit-fsck`) | Native `boot` service ordering |
| **Test ID Range** | `ART-BR-001` to `004` | `ART-BR-005` to `008` |

## 5. Conclusions & Migration Integration Notes

- **runit** offers finer-grained, parallel recovery but requires explicit supervise directory management. Recovery operations are service-isolated, aligning with invariant M-06 (recoverable operations).
- **openrc** provides a more traditional, script-driven model with stronger Gentoo/Funtoo compatibility. Boot recovery is globally coordinated, which simplifies fstab/initramfs repair but risks wider blast radius (countered by M-06 compensating procedures).
- **Integration for SunshineOS:** Adopt a hybrid transition catalog (`TC18` per architecture decisions) that maps runit service states to openrc init scripts during evolutionary milestones. Use the `evidence/` catalogue as the canonical seed for `Migration Planner` component (per `ARCHITECTURE_DECISIONS.md` component ownership matrix).  
- **Next Wave:** Extend catalogue to Artix `s6` and `dinit` if cross-init recovery semantics are required for milestone E020+.
