## Key Findings — runit vs openrc Recovery

### runit (`autonomy/artix/runit/`)
- **Boot sequence:** `runit-init` → `/etc/runit/1` → service `sv` trees under `/etc/runit/runsvdir/default/`
- **Recovery command:** `sv down <service>` / `sv up <service>`; `sv 1` through `sv 6` for runlevels
- **Artifact:** `recovery.log` captures `sv status` output and `sv timeout` behavior
- **Fallback:** `other/artix-boot-fallback.sh` uses `sv halt` and `sv poweroff` for clean umount before init switch

### openrc (`autonomy/artix/openrc/`)
- **Boot sequence:** `openrc-init` → `/etc/init.d/` scripts → `rc-service` / `rc-update` dependency resolution
- **Recovery command:** `rc-service <service> start`; `rc-status` for verification
- **Artifact:** `recovery.log` captures `rc-order` output and `rc_depend_strict` behavior
- **Fallback:** Same `other/artix-boot-fallback.sh` invokes `openrc-shutdown` before runit handoff

### Cross-Init Invariants (per M-05, M-06, M-09)
- All operations are **staged** in `autonomy/` before switching the running system (M-05)
- Each operation has an explicit **compensating procedure** documented in `evidence/` (M-06)
- Re-running discovery, planning, or interrupted execution does **not** produce uncontrolled duplication (M-09), verified by `ARTIX-BOOT-RECOV-009` invariant cross-check
