## Prioritized Defects & Exact Corrections
1. **Defect: Key reference without redaction**  
   *Location:* `reports/USER_MIGRATION_MANDATE_2026-11-21.md` (reference to "leftover keys" originating from user's 8 OpenRouter keys).  
   *Risk:* Potential credential leakage if key values later inserted.  
   *Correction:* Remove all key references. Use capability tokens or agent IDs instead. If keys are required, hash and store in `.openclaw/` vault, never in plaintext.

2. **Defect: Evolutionary ledger lacks immutable artifact schema**  
   *Location:* `evolution-engine/` (Section 4 of mandate describes illustrative structure but no concrete `EVS4` schema).  
   *Risk:* Violates M-02, M-03, M-07 if evolution events are not published as immutable artifacts with hash/signature/version.  
   *Correction:* Define `EVS4` schema as a published artifact in `evolution-engine/`: each event must have `event_id`, `schema_version`, `content_hash`, `digital_signature`, `dependency_ids`, `compatibility_meta`, `pub/deprecation_meta`. Implement generation and verification pipeline.

3. **Defect: Version identities not wired to artifact store**  
   *Location:* `evolution-engine/` (identities `E040`, `ME12`, `INV7`, `EVS4`, `TC18`, `B0-2026`, `B-1-2015`, `TP040` described but not linked).  
   *Risk:* Engine cannot independently verify or migrate between engine versions per M-03.  
   *Correction:* Wire each version identity to the Artifact Manager in `evolution-engine/`. Publish a `ME12` artifact package with content hash and signature. Ensure Orchestrator resolves source/target via these identifiers, not release numbers.

4. **Defect: "WAY superior" claim without measurable baseline**  
   *Location:* `reports/USER_MIGRATION_MANDATE_2026-11-21.md` (reparations tool claim).  
   *Risk:* Lacks verifiable metrics; future implementations may overpromise without baseline.  
   *Correction:* Replace hyperbolic claim with defined sustainability/stability metrics (e.g., mean time to recovery, package transition success rate). Add metrics schema to `evolution-engine/`/`reports/`.

5. **Defect: ISO/download research directives without sandbox constraints**  
   *Location:* Mandate text (downloads of Obarun, Windows 11 ISO, GarudaOS, CachyOS, etc.).  
   *Risk:* VM research could leak host state or introduce compromised ISOs.  
   *Correction:* Mandate all VM research in isolated QEMU/KVM domains with `--no-share-disks` and verified SHA256 checksums stored in `evidence/`. Add audit step before any code/tools adoption.
