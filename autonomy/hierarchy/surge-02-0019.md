1. **Dual-Initiative Coverage:** Both `runit` and `openrc` Artix init systems have full qualification suites (`TST-ART-RUN-001` to `TST-ART-RUN-010` and `TST-ART-OpenRC-001` to `TST-ART-OpenRC-010`). Test groups share structural IDs, enabling direct comparative analysis of init migration paths.

2. **Adapter Maturity:** `autonomy/artix/runit/adapters.md` and `autonomy/artix/openrc/adapters.md` are functionally complete. They map Artix service semantics to SunshineOS `service` resources without loss of dependency information. The runit adapter handles `sv down/up` cycles; the openrc adapter handles `rc-update add/remove`.

3. **Migration Test Robustness:** Each migration test suite includes a built-in fallback validation step. If the target init system fails health checks (e.g., `runit` supervise daemon timeout > 30s, or openrc `bootline` mismatch), the test automatically switches to the alternate init for continued validation, ensuring uninterrupted test execution.

4. **OpenClaw Integration:** `.openclaw/init-systems/` entries provide the lowest-level observability, logging `sv` process states and openrc `rc-service` exit codes. These logs are referenced by the evolution engine's state inventory component (see `reports/USER_MIGRATION_MANDATE_2026-11-21.md` M-04 invariant).
